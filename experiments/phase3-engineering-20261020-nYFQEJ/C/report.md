## Prioritized paths and responsibilities

Paths below are relative to `modules/caddyhttp/`; full canonical site IDs are in `site-index.md` and raw JSON. All cited response sites use `net/http.(ResponseWriter).WriteHeader` with unresolved concrete interface dispatch.

1. **Normal and handled responses [R/F].** `reverseproxy/reverseproxy.go:1452`, site `afda971af6b315c6470be2e69021b7d506d9cab2b784476fc4ca42e3f131a50a`, has reverse callers `reverseProxy:1381` and `CopyResponseHandler.ServeHTTP` (`copyresponse.go:83`). The former is called by `proxyLoopIteration:843`, then `Handler.ServeHTTP:710`. Status-only response replacement rejoins this path. However, `handle_response` routes execute at `reverseproxy.go:1357` and return without default finalization; arbitrary terminal handlers, another proxy, `copy_response_headers` plus a downstream handler, or fallthrough can produce the actual response. `copy_response_headers:145–178` copies headers but is not itself an emitter. [I] `staticresp.go:198,245` can replace headers and emit a replacement response. Forward-auth success intentionally continues to later handlers (`reverseproxy/forwardauth/caddyfile.go:181–202`): whether that later response counts as proxy-produced is unresolved.

2. **Errors before versus after commit [R/F].** Preparation failures (`reverseproxy.go:623–629`), unavailable upstreams, dial/timeout failures, exhausted retries, and incremental refusal return errors; they need not pass finalization. `refuseIncremental:2039` sets optional `Proxy-Status` and returns an error, not an HTTP status write. The server runs separate error routes (`server.go:797`) or writes status at `823/825/842` (site IDs in index). A wrapper local to the proxy is not passed into those later routes. Cancellation has a separate direct 499 write (`reverseproxy.go:852`, site `3b613437fc37adebd378c4832cc31b02c7cd65f55f00d7f9e2477b20b1b4f9f3`); a disconnected peer may receive nothing. After body-copy failure, finalization flushes and panics with `http.ErrAbortHandler` (`1464–1487`): preserve the original header/status, do not synthesize another response.

3. **Upgrade handshakes [R/F].** `finalizeResponse:1414` branches before ordinary response-header operations. `streaming.go:119` emits extended-CONNECT WebSocket 200, site `3c867c8fb3c996837d209296ad570c2337bfa4bc3818a30cfd2f7cb1895b30bd`; `:149` emits HTTP/1 upgrade 101, site `dcf640c7bd2d3d15026a165f7f9a2597766f7a5fb1e34ff89666563fc04d7eb3`. Header insertion must precede handshake commit, preserve upgrade-specific removals/normalization and retain detachment support. Invalid/mismatched upgrade types or non-writable upstream bodies return without an explicit error response (`:68–89`); inspect any implicit final response in validation. Hijack/flush failures cannot safely be treated as fresh precommit failures. Tunnel bytes are not additional HTTP responses.

4. **WebTransport [R/F].** `reverseProxy:1195` bypasses RoundTrip/finalization. `webtransport_transport.go:166` copies filtered headers and applies `header_down`; `:169` calls dependency `github.com/quic-go/webtransport-go@v0.13.0.(*Server).Upgrade`, whose `server.go:467` writes 200 and flushes (site `d78e9c7941411d64be89f01d63efe276f19ced962d8bfc5aa1b6e78e455080e9`). This supported graph reaches `Handler.ServeHTTP` at depth four. Upgrade receives the **unwrapped HTTP/3 writer**, so deferred wrapper-only policy can be bypassed. Dependency validation errors before that write return to server error handling; session pumping after success is not another header opportunity.

5. **Informational responses [R/F].** `Got1xxResponse` writes at `reverseproxy.go:1215`, site `63070b79b14c01fb5390068602aec185d5262b0e8155a598eca63b237e972aae`. It copies upstream headers temporarily, restores its own map and synchronizes against RoundTrip completion. The graph ends at the callback; callback execution is not proven by a reverse edge. Specify whether every permitted 1xx must carry the trace; preserve restoration and prevent duplication across hints/retries.

## Recommendation, tradeoffs and falsifiers

Reject `header_down`/finalization-only insertion as sufficient. Before coding, specify value generation/trust, one versus multiple values, user/upstream override rights, retry stability, informational responses and forward-auth ownership. [F] `copyHeader:1766` uses **Add**: setting an early value alone does not enforce uniqueness or authority. [I] outer `intercept/intercept.go:115–206` can buffer/replace output; `headers/headers.go:410` can mutate headers at commit.

Proposed responsibility change: select the intended trace once within its authorized lifetime; enforce the agreed policy at actual response commit for proxy-attributed responses, including server errors, with explicit pre-Upgrade WebTransport participation. Keep protocol/body/error ownership where it currently resides. This is a design obligation, not a verified wrapper design. Blanket server policy risks labeling unrelated responses; local wrappers miss later errors and naked-writer paths. A configuration-only solution may suffice if the contract permits overrides and narrower attribution. A passing full wire-level matrix under that contract could falsify the need for code changes.
