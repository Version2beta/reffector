# Historical discovery reconstruction and Caddy Class E analysis

## Assessment

The Caddy **Class E** result is valid for the later bounded blind control, but it is not a complete account of Reffector’s earlier contribution. A separate Reffector-assisted run, launched before Caddy PR #8269 was merged, produced a source-backed finding matching the same response-body and hijacked-connection cleanup defect. This earlier run did not reproduce the failure, and its prompt explicitly prioritized connection acquisition and cleanup; it is evidence of effect-directed investigative capability, not a neutral blind-discovery measurement or proof that it caused the PR.

The records show no demonstrated regression in Reffector’s analyzer. They show different investigation prompts and workflows, different binaries and query modes, and different source follow-up. The earlier run used focused response/close queries and then manually traced resource ownership. The Class E investigator used a broad inventory, did not inspect `streaming.go`, and did not pursue the upgrade-response cleanup path. A code change to make the analyzer infer missing cleanup is not justified by these records.

### Why the two Caddy results differ

The earlier run used two focused commands:

```sh
reffector -effect http.response -max-depth 2 -max-sites 100 -max-edges 300 ./modules/caddyhttp/...
reffector -operation Close -package /reverseproxy -direct -max-depth 2 -max-sites 70 -max-edges 150 ./modules/caddyhttp/...
```

They took 1.755 and 1.684 seconds respectively. The response output included `WriteHeader` sites in `streaming.go` at lines 119 and 149. The `Close` query did **not** itself identify the missing generic response-body close. The investigator followed up with source searches for `RoundTrip`, `Close`, response handling, and upgrade flow, then compared acquisition with separate close/transfer branches. The run records 12 source-search commands and 11 genuinely read files (`/Users/rob/Development/reffector_round2/runs/caddy-reffector-01/`). Thus the evidence supports Reffector as a navigation aid plus manual invariant reasoning; it does not show the analyzer detecting an absent obligation by itself.

The later blind run used a different binary (build metadata: Reffector commit `e0e62a296170881822b08bafd50c1f0b81104ce7`, `vcs.modified=true`; the earlier binary reports `5553a1d13011bf638148661f6a23bf561c3eef5a`, also modified). The saved reports are not a clean same-query, same-source, before/after analyzer comparison. The earlier response query showed generic `WriteHeader` sites; the later broad inventory showed `WriteHeader` and a goroutine site in the function. Neither emitted a `resource.release` site for `handleUpgradeResponse` on the pre-fix source. The Class E evaluation explicitly notes that a same-function breadcrumb could be argued as Class D under a broader relevance rule; its E classification means useful ownership evidence was absent and the investigator did not pursue it. This limitation should remain visible rather than treating the letter as an objective measure of all related output.

## Conclusion and next gate

The reconstructed pattern is consistent across the strongest artifacts: effect/site queries help select and navigate consequential operations; source inspection supplies the actual invariant, failure condition, and contrary evidence; tests or probes are needed to establish runtime behavior. Caddy and Restic provide source-backed examples of investigators reaching the later PR fix area, but only the evaluator’s separate Caddy regression comparison establishes failing pre-fix behavior. The rclone artifact is a known-case retrieval smoke, not historical provenance.

**Correction decision:** no Reffector analyzer implementation change is justified by Phase 2. The demonstrated issue was experimental comparability and observability: the successful Caddy run used focused effect queries plus cleanup-directed source follow-up, while the Class E blind control used a different prompt/tool path and stopped in other areas. Phase 1 already added bounded coverage/build metadata and optional event-ledger ingestion. The next experiment should preserve the blind/fixer separation, capture actual query/source-access events, and evaluate a fresh investigator against a frozen pre-fix snapshot. It should not disclose PR #8269, its patch, or these evaluator artifacts to that investigator.
