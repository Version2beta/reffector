# Source-directed investigation protocol

Use this protocol for a bounded, auditable investigation; a packet inventory is not code review.

1. **Pin inputs.** Record repository/source revision, analyzer revision and exact command/configuration, selected roots, and the analyzer artifact identity. Record coverage and each configured limit. State analyzer truncation, package-load limitations, and unavailable denominators honestly; do not convert static coverage into execution coverage.
2. **Survey breadth.** Select multiple independent consequential areas (for example distinct operation families, callers, lifecycle paths, or packages). Follow established, candidate, and unresolved relationships, retaining their status and alternative explanations. Do not promote a candidate edge to established reachability.
3. **Read source.** Retrieve actual repository source around selected operations and relevant callers, with canonical paths, exact requested ranges, and outcomes. Search results, analyzer output, and packet-builder excerpts are navigation/evidence summaries, not source reads. Record retrieval separately from substantive review; a successful read alone is not reviewed behavior.
4. **Review behavior.** For each area, record the behavior inspected and a falsifiable hypothesis with evidence that could refute it. Attempt focused tests or probes for promising hypotheses; record command and exit outcome, or why a probe was not attempted. Distinguish test exercise from source retrieval and function review.
5. **Disposition.** Record every candidate as accepted, rejected, or unresolved, with concise rationale and evidence references. Preserve uncertainty and contrary evidence. Do not require any arbitrary number of positive findings, and do not stop breadth because one candidate looks promising.
6. **Continue/stop.** Record wall-clock duration. Record active duration only when independently measured; otherwise say unavailable. Continue surveying independent areas until an explicit supervisor stop decision or the explicit hard time cap, whichever comes first. At the cap, stop work without fabricating a supervisor decision or active duration. Record an explicit supervisor decision and continue/stop rationale when provided. Pi transcripts do not encode supervisor decisions; missing decisions must remain explicitly missing, never inferred.

## Offline Pi transcript import

`pi_event_import.py TRANSCRIPT.jsonl --repository-root ROOT --ledger events.jsonl --report coverage.json [--run-metadata run.json] [--supervisor-decision decision.json]` accepts Pi 1.4 event streams and persisted session-entry JSONL. The ledger is accepted by `investigate.py --events`. It pairs `tool_execution_start`/`tool_execution_end` by call ID, imports assistant metadata at `message_end`, and recognizes terminal state only at `agent_settled` (`aborted: true` is aborted; `false` is completed). `agent_end` alone is not terminal. Duplicate observations collapse with all event line references; conflicting call IDs make coverage partial. Prompts and tool result/output fields are never copied. Reads use only requested range fields and do not claim returned extents. Direct Bash parsing accepts a single simple command, quoted search metacharacters, and only exact allowlisted leading Go environment assignments (`GOPROXY=off`, `GOSUMDB=off`, `GOTOOLCHAIN=local`, `GOFLAGS=-mod=readonly`, `GOWORK=off`); it does not evaluate shell syntax or retain those prefixes. Unquoted pipelines, substitutions, globs, unknown assignments, and other complex shell commands remain unclassified. Search output never becomes a read. Structured `exit_code` is retained exactly; absent exit/error facts remain unavailable. The optional run metadata accepts only run ID, start/end timestamps, measured wall duration, source/analyzer revisions, runner process exit code, and timeout status. Run ID is propagated as the available worker/run identity; no separate native worker ID exists. A measured wall duration emits a termination row with an evidence reference and unavailable active duration. A failed/timed-out runner without terminal `agent_settled` evidence records worker failure, never inferred completion. Supervisor JSON must explicitly provide continue/stop, timestamp, rationale, `scope_adequate`, and `another_phase_warranted`; otherwise the ledger records a missing decision. Native Pi events do not provide a worker ID or supervisor decision.
